# 音声文字起こしアプリ 論点・確認事項

実装に着手する前にユーザーに確認・決定してもらう必要がある項目をまとめる。
（DESIGN.md は確認済み・決定済みの設計のみを記載する方針のため、未決定の論点はここに分離している）

現時点で設計上の未確定の論点はなし（すべてDESIGN.mdに反映済み）。

## テスト実行時に発覚した問題

### [解決済み] OpenAI APIのクレジット残高不足（TEST.md フェーズ2/3）

- **発生日**: 2026-10-12 / **解決日**: 2026-10-12
- **内容**: `OPENAI_API_KEY` の認証自体は成功する（`client.models.list()` は200件取得できた）が、
  `audio.transcriptions.create` を3モデル（`gpt-4o-transcribe` / `gpt-4o-mini-transcribe` / `whisper-1`）
  すべてで実行したところ、全件が以下のエラーで失敗した。
  ```
  Error code: 429 - insufficient_quota / credit_balance_exhausted
  "You have no credits remaining. Add credits to continue using the API"
  ```
- **原因**: コードの問題ではなく、OpenAIアカウント側にクレジット（課金設定）が無い状態。
- **対応**: ユーザーがOpenAI側でクレジットを追加し解決。

### [解決済み] `gpt-4o-transcribe` のハルシネーション（無限ループ）

- **発生日**: 2026-10-12
- **内容**: TGLiAサンプル（8分）を `gpt-4o-transcribe` で文字起こしした際、後半で「はい、すいません。」という
  同一フレーズが80回以上連続して出力される現象が発生した。実際の音声内容を反映しない創作的な繰り返しであり、
  DESIGN.md 3章の「推論させない・逐語性」の原則に反する。
- **対応**: `gpt-4o-transcribe` を不採用とし、`whisper-1` を採用（DESIGN.md 3-2節に反映済み）。

### [保留] whisper-1でもハルシネーション（同一フレーズの繰り返し）が発生（TEST.md フェーズ4）

- **発生日**: 2026-10-12
- **内容**: `20261006_収支DBの可視化.m4a`（33.2分）のE2E本番処理で、チャンク4 [24:47 - 32:45] において
  「大冗談は少なくとも伝わるとしたら、あとはどうか関節的にでも仕組み化してやるかっていうのも」という
  フレーズが17回連続して出力された。
- **意味**: フェーズ3の8分サンプル比較ではwhisper-1に同様の問題は見られなかったが、全ファイルを通して処理すると
  whisper-1でも発生することが判明した。モデル選定だけでは根本解決にならない。
- **対応方針**: 現時点ではユーザー指示により未対応（残りのテストファイルを先に処理し、全体傾向を見てから対応を検討）。
  対応候補：同一フレーズの連続検出時に本文を書き換えず「[⚠️ 繰り返し検出：要確認]」等の警告マーカーを機械的に挿入する
  （「推論させない」原則を維持しつつ、聞き直し時にユーザーが優先確認すべき箇所を示す）。
- **その後の経過**: 残り2ファイルも全文処理し、簡易な繰り返し検出スクリプトでチェックした。
  - `2026-10-09 基板チャンク説明.m4a`（35.5分）：繰り返し検出なし。
  - `2026-10-09 TGLiA.m4a`（75.6分）：「おはようございます」等の短い挨拶が3〜4回連続する箇所を検出したが、
    文脈確認の結果、複数人が入室しながら挨拶・呼びかけをしている自然な会話であり、ハルシネーションではないと判断した。
  - 結論：3ファイル中1ファイル（33.2分）でのみ明確なハルシネーションを確認。発生は稀だが起こり得るため、
    上記の警告マーカー機能は今後実装候補として残す（現時点ではユーザー指示により未実装）。

### [保留] whisper-1のセグメントタイムスタンプは実際の無音（ポーズ）を反映していない

- **発生日**: 2026-10-12
- **内容**: Word出力（.docx）で、一部チャンクの本文が改行が全く無い数千文字の1段落になっている不具合をユーザーが発見。
  原因調査のため `20261006_収支DBの可視化.m4a` の先頭チャンク（0:00-8:08）を `whisper-1` の `verbose_json` で
  再取得したところ、140セグメントすべてで前セグメントとのギャップが常に `0.00` 秒だった。
- **意味**: DESIGN.md 3-2節で決定した「セグメント間ギャップ1.2秒以上で改行」というロジック（`transcribe.py` の
  `speaker_change_pause_sec`）は、whisper-1が実際の無音長とは無関係に機械的に約3〜4秒おきにセグメントを区切る
  （常に隙間なく連続）ため、ほぼ機能していない。チャンク3・4でまれに改行が入っていたのは、本当に長い沈黙が
  あった例外的なケースのみ。`docx_output.py` 自体にはバグはなく、上流の `.txt` の段落構造をそのまま渡しているだけ。
- **対応方針**: ユーザー指示により今回は未対応（修正せずこの記録のみ残す）。
  対応候補：ASRのセグメントギャップに頼らず、既存の `ffmpeg_utils.detect_silences`（chunking.pyで使用中）を
  各チャンク音声にも適用して実際の無音点を検出し、その時刻に最も近いwhisperセグメントの境界で改行を挿入する方式に
  切り替える。

- **対応**: `gpt-4o-mini-transcribe` を不採用とし、`whisper-1` を採用（DESIGN.md 3-2節に反映済み）。
